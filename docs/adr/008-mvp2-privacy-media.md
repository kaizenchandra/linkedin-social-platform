# 008: MVP-2 privacy and media lifecycle

Accepted 2026-09-27. Current member policy is authoritative; all cross-service checks fail closed with503. No privacy cache/projection. Pair locks serialize blocks with connection transitions. Content stores visibility with MEMBERS default; future reads use current state. Historical messages remain participant-accessible after blocking/removal. Cross-service policy checks have a documented check-to-commit race; there are no distributed transactions.

Media attachments use a dedicated REST edit command on media-service containing a client operationId, resource type/id and complete media ID list (empty removes). The media service orchestrates owner prepare, atomic media claims, owner commit and media confirmation. Owner operations are durably PREPARED/COMMITTED/ABORTED, keyed by operationId; payload reuse conflicts. Only media's scoped service credential may call owner attachment endpoints. Owner resource locks fence concurrent operations. Each media object can belong to one resource and only its uploader may attach it.

Reconciliation locks stale media and asks the owner to resolve the operation. Resolution aborts an outstanding PREPARED operation under the resource lock before reporting current references; a late commit then conflicts. A committed reference keeps its object. Failures leave metadata and bytes intact for a future bounded sweep. Abandoned upload grace defaults24h (minimum10min). An abandoned owner intent without a media claim can be aborted by the next prepare after10min. Attachment and download paths never call back into media, preventing recursive synchronous chains.

Objects start TEMPORARY, become READY after validation and acknowledged private-store write, then CLAIMED and ATTACHED. Only a reference authorized by the owner permits download; this also supports a committed reference whose media confirmation was interrupted. Removal immediately denies downloads even before physical cleanup. Cleanup deletes bytes then metadata; failed delete is retried. Backups/retained operational records mean this is not a complete-erasure guarantee.

S3-compatible SeaweedFS4.47 is local infrastructure; AWS SDK2.55.6 is pinned. Images use JDK ImageIO with strict input, pixel and normalized-output limits. A bounded worker is sufficient; Spring Batch would add job metadata and scheduling without a current benefit. Reassess for bulk workflows. Per-instance concurrent-upload limits are not global rate limits; the persisted hourly quota can overshoot by concurrent replicas and is abuse mitigation, not billing enforcement.
